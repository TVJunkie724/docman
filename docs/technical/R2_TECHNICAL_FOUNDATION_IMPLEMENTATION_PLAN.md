# Superseded - R2 Technical Foundation Implementation Plan

Dieser Plan darf nicht implementiert werden. Seine Feature-first-Struktur,
universelle Local-first-Autoritaet, Home-Hub-/Pairing-Ports und konkreten
Provider-Signaturen widersprechen F1, F2, F10, F11 und dem akzeptierten
Vault-/Account-/Assist-Modell.

Ein neuer C1 Implementation Contract muss aus folgenden Quellen erstellt und
vor Umsetzung geprueft werden:

- `docs/ROADMAP_REBUILD.md`;
- `docs/roadmap/PHASE_INDEX.md`;
- `docs/concepts/CONCEPT_F1_PROJECT_STRUCTURE.md`;
- `docs/concepts/CONCEPT_F2_STATE_MANAGEMENT.md`;
- `docs/concepts/CONCEPT_F10_LOCAL_STORAGE.md`;
- `docs/concepts/CONCEPT_F11_API_INTEGRATION.md`;
- `docs/technical/DECISION_ACCOUNT_VAULT_ASSIST_PRODUCT_MODEL.md`;
- `docs/technical/DECISION_VAULT_STORAGE_AND_CLOUD_PRODUCT_MODEL.md`.

Clean-Architecture-, Riverpod-, Drift- und Legacy-Isolationsideen duerfen nur
uebernommen werden, wenn der neue Plan sie anhand des aktuellen Repositories
erneut verifiziert. Branch-, Dateipfad-, Klassen- oder Command-Angaben dieses
historischen Plans sind nicht mehr gueltig.
